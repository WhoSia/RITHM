## 1. Distinguish clocks and admissible information
For measurement interval ending e, provider original public-release event p, client first confirmed receipt r: under provenance and nonanticipation e≤p≤r. A provider HTTP Date or historical archive upload date is NOT a certified per-observation publication clock. If reliable uncached negative probe l and first positive trusted receipt u are logged, provider p is **interval censored** in (l,u]; without valid l, only weak physical lower e; absent u, no finite upper bound. At decision t inside (l,u], whether the provider had already published is NOT IDENTIFIED. Even if provider p≤t, the client cannot use an unreceived observation: **operational legal feature requires trusted client r≤t**. For a 10-minute source pair, both 5-minute components must be individually received, consecutive, and nonfuture. Missing receipt => fallback to a previously demonstrably received pair or already loaded calendar features.
Example: sensor end 10:00, true negative 10:07, first positive 10:13 -> provider release could be 10:08 or 10:12. Publication at decision 10:10 is NOT identified; client receipt after decision cannot authorize the record in either world.
A certified bound on **provider publication** is weaker than a certified bound on **client delivery**. No source 2025 per-bin signed release record or validated client stream is currently held. Software verified=True does not confer independent authority.
